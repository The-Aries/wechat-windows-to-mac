# 把微信聊天记录从 Windows 搬到 Mac：一次完整的整理、迁移与核对记录

这份文档记录了一次真实的微信迁移：为什么要做、遇到了什么问题、怎么做的、用了哪些工具、哪些成功了、踩了哪些坑。
最后附上一组**只读**的核对脚本（[`tools/`](tools/)），用来回答一个问题：**迁移之后，到底少了什么？**

所有删除和迁移都由本人在**微信官方客户端**里完成。脚本只读取数据库的**副本**，从不修改微信的任何数据。

## 1. 结论先说

- **官方迁移（Windows → 手机 → Mac）能把文字、图片、视频、文件和语音都带过去**，前提是源设备上真的有这些文件。
- 约 190 万条消息、45 GiB 的账号，最终逐条核对的结果：在聊天列表里能看到的聊天中，Mac 只少了 1,948 条，其中约八成是通话记录和**本来就没有声音的语音**，一半以上集中在 2019–2020 年。
- 最容易出错的不是迁移本身，而是**判断有没有缺**。按文件名比对会把大量"换了文件名"的图片误判为缺失，必须用消息记录核对。

## 2. 初衷

我有三个微信账号，聊天记录都在一台 Windows 电脑上，最大的账号从 2019 年开始。我想换到 MacBook Air 上用微信，要求是：

1. **迁移前先清理**：删掉不再需要的好友和聊天，只带走想留的。
2. **真正的文件也要过去**：原图、视频、语音、文件，不只是文字。
3. **不能丢东西**：这些年换过电脑、手机和微信版本，移动硬盘里有好几份旧备份。要确认清理后，没有想留的内容只存在于旧备份里。
4. **原始数据不能被破坏**：在确认成功之前，Windows 上的数据和所有备份都保持原样。

## 3. 遇到的问题

| 问题 | 为什么麻烦 |
| --- | --- |
| 分不清账号 | 电脑上的文件夹名是内部 ID（`wxid_…`），看不出是哪个昵称 |
| 数据库是加密的 | 不解密就无法统计消息，也无法核对迁移结果 |
| 旧数据分散 | 移动硬盘里有：旧的 4.x 快照、3.x 时代的文件夹、2020 年的 Android 备份、迁移前的备份 |
| 官方迁移是"合并" | 不会同步删除。手机上还留着的旧聊天，会重新出现在电脑上 |
| Mac 端难以解密 | macOS 的 SIP 和应用签名保护，使普通的内存扫描读不到 Mac 微信的数据库密钥 |

## 4. 怎么做的

### 4.1 原则："只读"是什么意思

**我们从来没有修改过微信的任何数据库。** 唯一一次往微信文件夹里写东西，是在 Mac 上测试时临时复制了 6 个图片文件，测试后已经移走。

- 要看数据时，先把数据库文件（连同 `-wal`、`-shm`）**复制**到临时文件夹，在副本上解密、以只读方式打开、统计，用完就删除。原文件不动。
- 删好友、删聊天、迁移，全部由本人在**微信官方界面**里操作。
- 每做一步，就再复制一份数据库核对：确认删掉的确实是想删的，留下的都还在。

能读数据库，不等于改了数据库。直接改微信的数据库可能导致客户端报错、数据损坏、和服务器状态不一致，而且无法撤销。
所以即使发现 Mac 上缺了一些消息，也**没有**直接往 Mac 的数据库里写数据。

### 4.2 步骤

1. **确认账号身份**：微信登录状态下，从进程内存取得数据库密钥，在副本上解密联系人库，找到"自己"那一条，把内部 ID 和昵称对上。
2. **建立基线**：清理前统计会话数、每年的消息数、各类消息数、每个聊天的附件数量和大小。
3. **清理**：
   - 列出"没有备注的好友"，按聊天条数排序，由本人逐个决定删或留；决定保留的不再推荐删除。
   - 列出"非好友的聊天"，做成可勾选的网页（每页 10 个，默认全部保留），由本人勾选。
   - 在官方界面里删除。
4. **小账号先试**：两个小账号先走一遍 Windows → 手机 → Mac，按文件逐个核对。
5. **找出所有旧数据**：在移动硬盘上按特征全盘搜索（`MSG*.db`、`EnMicroMsg.db`、`message_*.db`、`wxid_*`、`xwechat_files`、`WeChat Files` 等）。
6. **逐份核对旧数据**（见 6.2）：确认旧备份里有、电脑上没有的内容，除了 4 个文档以外，都属于本人删除的聊天。
7. **正式迁移主账号**：Windows → 新手机 → Mac；另外把旧手机也导入了一次。
8. **迁移后核对**：
   - 先做文件级比对，发现大量"缺失"，后来证实大部分是误判（见 6.3）。
   - 最后取得 Mac 端的数据库密钥，**逐条比对消息**，得到可信的结论。

## 5. 最终结果

| 项目 | 结果 |
| --- | --- |
| 小账号（第二个账号） | 视频 313/313 相同；文件 36 个中 35 个相同，另 1 个只是重名后缀不同；附件基本一致 |
| 主账号（约 194 万条消息） | 在聊天列表可见的聊天里，Mac 少 1,948 条：通话记录 917、语音 622、链接或文件 295、文字 71，其余为表情、系统消息和图片 |
| 少掉的语音 | 在 Windows 上就只有消息记录、**没有音频**；在查过的所有旧备份里也都找不到，所以迁移时被跳过 |
| 不在聊天列表里的残留聊天 | 32 个、约 5.8 万条消息没有迁移。它们在 Windows 上本来就看不到 |
| Mac 上有、Windows 上没有的消息 | 只有 16 条（推测来自旧手机） |
| 删掉的聊天 | 又回到了 Mac 和 Windows 上，推测与导入旧手机有关（本人决定不再处理） |
| 旧备份 | 2020 年 Android 备份的 83,538 条消息全部已在电脑上；旧 4.x 快照里有而电脑上没有的消息，都属于本人删除或清空的聊天；另有 4 个文档只在快照里还有文件 |

## 6. 踩过的坑

### 6.1 迁移

- **迁移是合并，不是同步。** 在 Windows 上删掉的聊天，只要手机上还有，就会回到电脑上。导入旧手机，会把旧手机上还留着的已删聊天带回来。
- **重新导入可以补上缺的内容。** 迁移是合并，重新导入不会删掉已有的记录。
- **不要为了"干净"清空旧手机。** 旧手机上可能有别处没有的消息。
- 同一个账号同时只能登录一台电脑（Windows 或 Mac）。在 Mac 上登录，Windows 会被挤下线。
- 大账号迁移时间长：所有设备都接电源，Mac 设置为不休眠，手机关掉自动锁屏。

### 6.2 旧数据

- **压缩包里可能藏着更早的版本。** Android 备份工具的文件夹里有一份解压出来的 `EnMicroMsg.db`，压缩包 `com.tencent.mm.tar.gz` 里还有一份更早的同名数据库，带一个 `-wal`（3 次已提交的写入）。两份都要查，`-wal` 也要合进去。
- **文件大小不说明内容多少。** 几个只登录过一天的 3.x 账号，`MSG0.db` 都正好是 50 MiB，看起来是预分配的空间。
- **3.x 数据库的密钥**一般只能从登录了该账号的 3.x 客户端读取。没有密钥时，可以比对附件文件夹：3.x 的 `FileStorage/MsgAttach/<md5>` 和 4.x 的 `msg/attach/<md5>` 用的是同一个 md5。
- **Android 的 `EnMicroMsg.db`**：密钥是 `md5(IMEI + uin)` 的前 7 位，我们这份备份用的是固定 IMEI `1234567890ABCDEF`（很多新版 Android 都是这样）。

### 6.3 核对

- **按文件名比对图片会严重误判。** Windows 上有一类 `_W` 结尾的图片文件。经过手机中转后，Mac 上很可能用另一个文件名、另一种格式保存同一张图。按文件名甚至按文件内容比对，看起来缺了 1.2 万张图，但抽查的图片在 Mac 上都能正常打开大图。
- **抽查要做前后对比。** 第一次"复制图片后能看"的测试没有先看复制前的状态，不能证明任何事。换一组图，先确认复制前就能打开，才证明了"本来就没缺"。
- **"有消息"不等于"有内容"。** 4.x 的语音消息记录和音频分开存放：消息在 `message_*.db`，音频在 `media_*.db` 的 `VoiceInfo` 表。有记录没音频的语音，迁移时会被整条跳过，Mac 上看不到这条语音。
- **用服务器 ID 比对消息，不用内容。** Android 和电脑版存储部分 emoji 的编码不同，同一条消息内容可能不一样。本地消息没有服务器 ID，按"时间 + 类型"比对。
- **消息内容可能经过 zstd 压缩**（开头是 `28 b5 2f fd`）；基本消息类型用 `local_type & 0xFFFFFFFF` 取。
- **Windows 和 Mac 的数据库密钥不同。** 用 Windows 进程里的密钥解不开 Mac 的库。

### 6.4 Mac 端取得密钥

在 macOS 上，系统保护会阻止调试已签名的微信。可行的方法是：
1. 正常退出微信，把 `WeChat.app` **复制一份**。
2. 给副本做 ad-hoc 签名（`codesign --force --deep --sign -`）。
3. 用 LLDB 启动副本，在 `CCKeyDerivationPBKDF` 处下断点，读出每个数据库的密钥。
4. 用数据库第一页的 HMAC 验证密钥。
5. 结束后删掉副本，打开原版微信。

原版应用不修改，SIP 不关闭，也不需要 root。副本需要在手机上确认登录一次。脚本见 [`tools/mac_capture_keys.py`](tools/mac_capture_keys.py)，思路来自 [acmerfight 的 gist](https://gist.github.com/acmerfight/0a01249ef72970d07a2603dbb629e80f)。

### 6.5 其他

- **用脚本删除文件是永久删除，不经过回收站。** 需要能恢复时，通过回收站或废纸篓删除。
- 在 Mac 上读取 exFAT 移动硬盘时，Finder 会写入 `._*` 和 `.DS_Store`。只读核对时，只用 `find`、`stat`、`cat`、`tar -t` 这类不写入的命令。

## 7. 工具

### 7.1 推荐的第三方工具

| 工具 | 用途 | 我们的结果 |
| --- | --- | --- |
| 微信官方客户端 | 删除、迁移 | 唯一用来修改数据的方式 |
| [WeChatMsg-4x](https://github.com/chenanhan230-del/WeChatMsg-4x)（GPL-3.0） | Windows 上从运行中的微信取 4.x 密钥并解密 | 35 个库全部解开；本仓库的脚本依赖它 |
| [acmerfight 的 gist](https://gist.github.com/acmerfight/0a01249ef72970d07a2603dbb629e80f) | Mac 上取 4.x 密钥的方法 | 按其思路自写脚本，29 个库中解开 28 个（核对需要的消息、会话、联系人库都在内） |
| [WeFlow](https://github.com/334456777/WeFlow) | 识别账号目录 | 能找到账号；取密钥那次微信没运行，未成功 |

### 7.2 本仓库的脚本（`tools/`，全部只读）

需要 Python 3.10+、`pip install -r tools/requirements.txt`，以及一份 WeChatMsg-4x（用 `--wx4` 指定路径）。

| 脚本 | 回答的问题 |
| --- | --- |
| `inventory_account.py` | 账号文件夹里各部分有多少文件、多大？迁移前后各跑一次 |
| `baseline_account.py` | 有多少会话、每年多少消息、各类消息多少？清理和迁移前先留一份 |
| `check_voice_audio.py` | 哪些语音没有音频（迁移时会被跳过）？能在旧备份里找到吗？ |
| `compare_devices_messages.py` | 另一台设备（例如 Mac）相比 Windows，按聊天逐条少了哪些消息？ |
| `mac_capture_keys.py` | 在 Mac 上取得 4.x 数据库密钥（重签名副本 + LLDB） |
| `compare_4x_snapshot_messages.py` | 旧的 4.x 快照里有、现在没有的消息，是聊天还在（真缺）还是聊天被删了？ |
| `compare_4x_snapshot_media.py`、`attribute_4x_snapshot_media.py` | 旧快照里的文件现在还在吗？按月份存放的文件属于哪个聊天？ |
| `decrypt_android_enmicromsg.py`、`compare_android_vs_4x.py` | 解密旧 Android 数据库（含 `-wal`），和电脑版逐条比对 |
| `compare_3x_4x_attach_coverage.py` | 不用密钥：4.x 是否覆盖了 3.x 的每个聊天和月份的附件？ |

输出只有数量、日期和聊天的 md5 前 8 位。加 `--show-names` 才显示名字，任何脚本都不输出消息正文和密钥。

## 8. 还没做完的事

- **旧手机上的语音。** 有 624 条语音在电脑和所有旧备份里都没有音频。唯一没查过的是旧手机：可以打开对应的聊天，看能不能播放。能播放的话，**只迁移那几个聊天**，不要整机迁移，否则删掉的聊天会再回来。
- 不在聊天列表里的 86 个残留聊天（约 22 万条消息、0.5 GB）还留在 Windows 的数据库里。聊天列表里看不到它们，没有找到官方的删除入口。为了不冒险，没有直接改数据库。

## 9. 说明

- 只在自己的账号和自己的设备上使用这些方法和脚本。
- 取得密钥和解密，只是为了核对自己的数据。不要把密钥、数据库或聊天内容上传或分享给任何人。
- 微信的版本和数据结构会变化。本文基于 Windows 微信 4.2.0.12（清理和核对旧数据时）和 4.2.0.13（正式迁移时，2026-11-10 自动更新），Mac 微信 4.1.15，macOS 27.2.1，时间是 2026 年 11 月。
